Construcción de interfaces web modernas

01 — HTML5

Estructura de una web — paso a paso

Piensen en HTML como el esqueleto de una página. Sin HTML no existe nada en el navegador. Vamos a construir un documento HTML desde cero, línea por línea.

Paso 1

Crear el archivo y declarar HTML5

Abran su editor de código (VS Code). Creen un archivo llamado index.html. Lo primero que van a escribir es esto:

index.html
<!DOCTYPE html>

Esta línea le dice al navegador: "este archivo es HTML5". Sin ella, el navegador entra en un modo antiguo y las cosas se ven raro. Es una sola línea, siempre va primero, y nunca cambia.

Paso 2

Abrir la etiqueta html con idioma

Debajo del DOCTYPE, abran la etiqueta <html> y díganle que el idioma es español:

index.html
<!DOCTYPE html>
<html lang="es">

</html>

El lang="es" ayuda a los lectores de pantalla a pronunciar bien el texto y a Google a saber en qué idioma está su página. Todo lo demás va a ir DENTRO de estas dos etiquetas.

Paso 3

Agregar el head — la información invisible

Dentro de <html>, lo primero es el <head>. Aquí van datos que el usuario NO ve, pero el navegador necesita:

index.html
<!DOCTYPE html>
<html lang="es">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mi Sitio Web</title>
  <link rel="stylesheet" href="styles.css">
</head>

</html>
*

¿Qué hace cada línea?

charset="UTF-8" — para que se vean bien las ñ, tildes y caracteres especiales.

viewport — hace que la página se vea bien en celulares (sin esto se ve chiquita).

title — el texto que aparece en la pestaña del navegador.

link — conecta nuestro archivo CSS (los estilos).

Paso 4

Agregar el body — lo que el usuario VE

Después del </head>, abran el <body>. Todo lo que el usuario ve en la página va aquí adentro:

index.html
<!DOCTYPE html>
<html lang="es">

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mi Sitio Web</title>
  <link rel="stylesheet" href="styles.css">
</head>

<body>
  <!-- Aquí va todo lo visible -->
</body>

</html>
!

Regla importante: Nada visible va en el <head>. Nada de metadatos va en el <body>. Si ponen un <p> en el head, no se va a ver.

Paso 5

Llenar el body con etiquetas semánticas

Ahora viene la parte importante. Dentro del <body> NO metan todo en <div>. Usen etiquetas que le dicen al navegador QUÉ es cada cosa:

index.html — dentro del body
<body>

  <header>
    <nav>
      <a href="#inicio">Inicio</a>
      <a href="#servicios">Servicios</a>
      <a href="#contacto">Contacto</a>
    </nav>
  </header>

  <main>
    <section id="inicio">
      <h1>Bienvenidos a mi sitio</h1>
      <p>Este es el contenido principal.</p>
    </section>

    <section id="servicios">
      <h2>Nuestros servicios</h2>
      <article>
        <h3>Diseño web</h3>
        <p>Creamos sitios modernos.</p>
      </article>
    </section>
  </main>

  <footer>
    <p>&copy; 2025 Mi Empresa</p>
  </footer>

</body>

Eso es todo. Abran este archivo en el navegador y van a ver el contenido. Sin CSS se ve feo, pero la ESTRUCTURA ya está.

¿Qué etiqueta uso para qué?

<h>

<header>

El encabezado. Logo + menú de navegación. Va arriba de todo.

nav

<nav>

Los enlaces de navegación. Va DENTRO del header.

<m>

<main>

El contenido principal. Solo UNO por página.

sec

<section>

Un bloque temático: "Servicios", "Nosotros", "Contacto".

art

<article>

Contenido independiente: un post, una noticia, un producto.

<f>

<footer>

El pie de página. Copyright, links, redes sociales.

!

Error comun: Escribir <div class="header"> en vez de <header>. Se ve igual, pero el navegador y los lectores de pantalla no saben qué es.

Paso 6

Agregar un formulario

Los formularios son la forma de recibir datos del usuario. Cada campo necesita un <label>. Sin label, una persona ciega no sabe qué escribir ahí.

HTML — agregar dentro de una section
<section id="contacto">
  <h2>Contacto</h2>

  <form>
    <label for="nombre">Nombre:</label>
    <input type="text" id="nombre" required>

    <label for="email">Email:</label>
    <input type="email" id="email" required>

    <label for="mensaje">Mensaje:</label>
    <textarea id="mensaje" rows="4"></textarea>

    <button type="submit">Enviar</button>
  </form>
</section>
*

¿Cómo funciona? El for="nombre" del label se conecta con el id="nombre" del input. Hacen clic en el texto "Nombre:" y el cursor va al campo. Pruébenlo abajo:

Hagan clic en el texto "Nombre completo" — el cursor va al input gracias al label.
Paso 7

Imágenes y enlaces

Imágenes

  • <img src="foto.jpg" alt="Descripción">
  • alt="" vacío si es solo decoración
  • loading="lazy" para carga diferida

Enlaces

  • <a href="url">Texto</a> — enlace básico
  • target="_blank" abre en pestaña nueva
  • href="#seccion" para navegación interna

Con esto ya tienen TODO el HTML que necesitan para una landing page. Ahora vamos a darle estilo con CSS.

02 — CSS Moderno

Dándole estilo — paso a paso

Ya tienen la estructura HTML. Ahora vamos a hacer que se vea bien. Creen un archivo styles.css en la misma carpeta que su index.html y sigan estos pasos.

Paso 1

El reset — siempre empiecen con esto

Lo primero que van a escribir en su CSS es un reset. Esto elimina los márgenes y paddings que el navegador pone por defecto y arregla cómo se calculan los tamaños:

styles.css
*, *::before, *::after {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

¿Qué es box-sizing: border-box? Sin esto, si dicen "esta caja es de 300px" y le agregan 20px de padding, termina midiendo 340px. Con border-box, 300px es 300px incluyendo todo. Siempre úsenlo.

Entiendan el Box Model

Todo elemento HTML es una caja con 4 capas. De adentro hacia afuera:

content

content = el texto o imagen. padding = espacio interno (entre contenido y borde). border = el borde visible. margin = espacio externo (entre esta caja y las demás).

Paso 2

Definir variables — colores, fuentes y espaciados

Antes de escribir cualquier estilo, definan sus colores y fuentes en un solo lugar. Así, si quieren cambiar algo, lo cambian UNA vez:

styles.css — agregar debajo del reset
:root {
  --color-primary: #028090;
  --color-dark: #1a202c;
  --color-light: #f7f7f7;
  --color-white: #ffffff;
  --font-body: 'Inter', sans-serif;
  --spacing-sm: 0.5rem;
  --spacing-md: 1rem;
  --spacing-lg: 2rem;
  --spacing-xl: 4rem;
}

Después usan estas variables con var(--nombre). Ejemplo: color: var(--color-primary).

Si el cliente dice "cambiá el azul por verde", cambian UNA línea en :root y todo se actualiza.

Paso 3

Estilos base del body

Ahora denle estilos generales al body — la fuente, el color del texto, y el alto de línea:

styles.css
body {
  font-family: var(--font-body);
  color: var(--color-dark);
  line-height: 1.6;
  background: var(--color-white);
}

line-height: 1.6 hace que el texto tenga espacio entre líneas y sea más fácil de leer. Si lo dejan en 1, las líneas se pegan.

Paso 4

Flexbox — alinear cosas en una fila

Flexbox sirve para distribuir elementos en UNA dirección: fila o columna. Lo van a usar para el navbar, para centrar cosas, para separar elementos.

Ejemplo: quieren el logo a la izquierda y el menú a la derecha:

styles.css
header {
  display: flex;              /* activa flexbox */
  justify-content: space-between; /* separa los hijos */
  align-items: center;        /* centra vertical */
  padding: var(--spacing-md);
}

Resultado:

justify-content: space-between
Logo
Menu
Login
*

¿Qué hace cada propiedad?

display: flex — activa flexbox en ese contenedor.

justify-content — distribuye los hijos en el eje horizontal (space-between, center, flex-end...).

align-items — alinea los hijos en el eje vertical (center, flex-start, flex-end...).

gap — espacio entre cada hijo (mejor que usar margin).

Paso 5

CSS Grid — layouts de dos dimensiones

Grid trabaja en DOS ejes (filas Y columnas). Lo van a usar para el layout general de la página y para grillas de tarjetas.

Ejemplo: una sección de servicios con 3 columnas:

styles.css
.servicios {
  display: grid;
  grid-template-columns: repeat(3, 1fr); /* 3 columnas iguales */
  gap: var(--spacing-lg);
}

También pueden nombrar las áreas del layout:

styles.css
.pagina {
  display: grid;
  grid-template-columns: 200px 1fr 200px;
  grid-template-areas:
    "header  header  header"
    "sidebar main    aside"
    "footer  footer  footer";
  gap: 1rem;
}

Resultado:

grid-template-areas
Header
Sidebar
Main Content
Aside
Footer
*

Regla simple: Flexbox para componentes chicos (navbar, una fila de botones, una card). Grid para el layout general de la página o grillas de contenido.

Paso 6

Hover y transiciones — que las cosas respondan

Cuando el usuario pasa el mouse por un botón, tiene que pasar algo. Sin esto, el botón se siente muerto:

styles.css
.boton {
  background: var(--color-primary);
  color: white;
  padding: var(--spacing-sm) var(--spacing-lg);
  border: none;
  border-radius: 6px;
  cursor: pointer;
  transition: background 0.2s;  /* suaviza el cambio */
}

.boton:hover {
  background: #026670;  /* un tono más oscuro */
}

Paso 7

Tipografía y espaciado

Tipografía

  • Máximo 2 fuentes: títulos y cuerpo
  • Usen rem en vez de px para tamaños
  • line-height: 1.5 mínimo para texto de párrafo
  • Solo 2 pesos: regular (400) y bold (700)

Espaciado

  • Escala consistente: 8, 16, 24, 32, 48px
  • Defínanla en variables y úsenla siempre
  • Más espacio entre secciones, menos entre elementos cercanos
  • gap en Flex/Grid en vez de margin

Con estos 7 pasos ya tienen un CSS completo. Ahora vamos a hacerlo responsive.

03 — Responsive Design

Que se vea bien en cualquier pantalla

Más del 60% de las visitas web son desde celulares. Si su página no funciona en móvil, están perdiendo a más de la mitad de sus usuarios.

Desktop > 1024px
Tablet 768 – 1024px
Mobile < 768px
Paso 1

Mobile First — empiecen por el celular

El CSS que escriben SIN media query es para celular. Después usan @media para AGREGAR estilos cuando la pantalla crece:

styles.css
/* Esto es para celular (sin media query) */
.servicios {
  display: grid;
  grid-template-columns: 1fr;  /* 1 columna */
  gap: 1rem;
}

/* Cuando la pantalla tenga 768px o más = tablet */
@media (min-width: 768px) {
  .servicios {
    grid-template-columns: repeat(2, 1fr); /* 2 columnas */
  }
}

/* Cuando la pantalla tenga 1024px o más = desktop */
@media (min-width: 1024px) {
  .servicios {
    grid-template-columns: repeat(3, 1fr); /* 3 columnas */
  }
}
*

Usamos min-width, no max-width. El CSS base es para móvil y las media queries AGREGAN cuando la pantalla crece. Es más fácil agregar complejidad que quitarla.

Paso 2

clamp() — tipografía que se adapta sola

En vez de cambiar el tamaño de título en cada media query, usen clamp(). Le dicen un mínimo, un máximo, y cómo escala:

styles.css
h1 {
  /* mínimo 1.8rem, escala con el ancho, máximo 3rem */
  font-size: clamp(1.8rem, 1.4rem + 2vw, 3rem);
}

Eso es todo. El título se adapta solo. En celular es 1.8rem, en desktop llega a 3rem, y en el medio escala suavemente.

Paso 3

Grid que se adapta sin media queries

styles.css
.auto-grid {
  display: grid;
  grid-template-columns: repeat(
    auto-fit,
    minmax(min(100%, 18rem), 1fr)
  );
  gap: 1.5rem;
}

Esto crea un grid donde las columnas se acomodan solas. Si caben 3, muestra 3. Si solo cabe 1, muestra 1. Sin una sola media query.

04 — UX/UI

Que se vea bien y funcione mejor

No necesitan ser diseñadores. Con estos 6 principios sus sitios se ven profesionales. La diferencia entre amateur y profesional casi siempre es espaciado y consistencia.

01

Jerarquía visual

Lo más importante se ve primero: más grande, más oscuro, más arriba. Si todo tiene el mismo tamaño, nada destaca.

02

Contraste

Texto oscuro sobre fondo claro. Si cuesta leerlo, está mal. Ratio mínimo 4.5:1.

03

Espaciado

Den aire a los elementos. El espacio blanco no es desperdicio — es lo que hace que una página se sienta limpia.

04

Consistencia

Si un botón es azul y redondeado, TODOS los botones primarios deben serlo. Misma función = mismo estilo.

05

Feedback

Cuando el usuario hace algo, debe pasar algo visible. Hover, loading, éxito, error. Nunca dejen al usuario preguntándose "¿funcionó?".

06

Navegación clara

El usuario nunca debe sentirse perdido. Máximo 7 ítems en el menú. Siempre debe ser obvio dónde están.

05 — Accesibilidad

La web es para todos

Accesibilidad no es "algo lindo de tener". Si su sitio no funciona para personas con discapacidad, están excluyendo gente. Si usan HTML semántico, ya tienen el 80% resuelto.

  • +
    HTML Semántico — Usen <button> para botones, no <div onclick>. Un div con onclick no funciona con teclado.
  • +
    Labels en formularios — Todo input necesita un label con for="id". El placeholder no cuenta — desaparece al escribir.
  • +
    Navegación por teclado — Traten de usar su sitio solo con Tab, Enter y Escape. ¿Pueden llegar a todo?
  • +
    Contraste — Texto normal: ratio 4.5:1 mínimo. Verifiquen en webaim.org/resources/contrastchecker.
  • +
    Alt en imágenes — Si la imagen comunica algo: alt="descripción". Si es decoración: alt="" vacío.

<div class="boton" onclick="cerrar()">Cerrar</div>

<!-- BIEN -->

<!-- MAL -->

06 — Uso de IA

La IA como herramienta, no como muleta

La IA puede generar código en segundos, pero si no entienden lo que genera, no les sirve de nada. El objetivo es usarla para ir más rápido, no para evitar aprender.

1

Dar el input

Screenshot, wireframe o descripción clara de lo que quieren.

2

Recibir estructura

La IA genera HTML. Revisen que use semántica, no puro div.

3

Revisar componentes

¿Separó header, cards, footer? ¿Es reutilizable?

4

Revisar CSS

¿Usa variables? ¿Flexbox/Grid? ¿Es responsive?

5

Entender cada línea

Si no saben qué hace una propiedad, pregunten antes de usar.

6

Ajustar y mejorar

El código de IA es un borrador. Modifíquenlo, háganlo suyo.

!

Regla de la clase: Si les pregunto "¿qué hace esta línea?" y no pueden explicarlo, no deberían estar usándola. La IA ahorra tiempo de escritura, no de aprendizaje.

Qué revisar en código generado por IA

  1. ¿Es semántico? — ¿Usa header, nav, main, section? ¿O es todo div?
  2. ¿Es accesible? — ¿Labels, alt, botones reales?
  3. ¿Es responsive? — Achiquen el navegador. ¿Se rompe?
  4. ¿Usa variables? — ¿Colores hardcodeados o custom properties?
  5. ¿Lo entienden? — Lean cada propiedad CSS.
07 — Taller práctico

Construyan su Landing Page

Apliquen todo lo que vimos. Pueden usar la IA, pero tienen que entender cada línea. Al final voy a revisar su código y les voy a preguntar sobre lo que hicieron.

Estructura HTML

  • DOCTYPE, html, head, body completo
  • Header con navegación funcional
  • Hero section con título y CTA
  • Sección de features o servicios
  • Formulario de contacto con labels
  • Footer con links

Estilos CSS

  • Variables CSS para colores, fuentes, spacing
  • Flexbox para componentes
  • CSS Grid para el layout general
  • Hover y focus en todo lo interactivo
  • transition para suavizar cambios
  • Paleta de colores en :root

Responsive

  • Mobile First (sin media query = móvil)
  • Breakpoint tablet: 768px
  • Breakpoint desktop: 1024px
  • Imágenes con max-width: 100%
  • Tipografía con clamp()
  • Menú que funcione en móvil

Calidad

  • HTML semántico (nada de div para todo)
  • Labels en todos los inputs
  • Alt en todas las imágenes
  • Funciona con teclado (Tab/Enter)
  • Código limpio y ordenado
  • Pueden explicar cada línea

Pasos para construir su landing

  1. Crear archivos — Una carpeta con index.html y styles.css.
  2. HTML primero — DOCTYPE, html, head, body. Dentro del body: header, main con secciones, footer. Abran en navegador sin CSS — si se lee bien, la estructura está bien.
  3. Reset + variables — En el CSS: box-sizing border-box, y todas sus variables en :root.
  4. Estilos mobile — Todo en una columna. Que se lea bien en celular.
  5. Media queries — @media (min-width: 768px) para tablet, 1024px para desktop.
  6. Hover y transiciones — Que los botones y links reaccionen al mouse.
  7. Revisar — Achiquen el navegador. Naveguen con Tab. ¿Todo funciona?
